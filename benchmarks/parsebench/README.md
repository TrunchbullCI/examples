# ParseBench Trunchbull port

An unofficial port of [ParseBench](https://github.com/run-llama/ParseBench)
(LlamaIndex, Apache-2.0) for Trunchbull. It is not maintained by or affiliated
with the upstream project and does not replace it. Cite and report dataset
issues upstream:
[paper](https://arxiv.org/abs/2604.08538),
[dataset](https://huggingface.co/datasets/llamaindex/ParseBench),
[leaderboard](https://parsebench.ai).

The model parses one document page into layout-annotated markdown, and the
grader scores it with upstream ParseBench's own Python evaluation.

| Pin              | Value                                                                    |
| ---------------- | ------------------------------------------------------------------------ |
| Upstream code    | `run-llama/ParseBench` @ `cb4c20d61c9156fdeb6fb63308349000bbd8536e` (1.0.5) |
| Dataset          | `llamaindex/ParseBench` @ `2805a1d940f95a203e0ae4b88be9934f7765b3fc`       |
| Prompt           | Upstream `SYSTEM_PROMPT_LAYOUT` / `USER_PROMPT_LAYOUT` (Core11, 0–1000 boxes) |
| Grader pipelines | `anthropic_opus_5_5_parse_with_layout_file` (PDF), `anthropic_sonnet_5_parse_with_layout` (PNG) |

Exact hashes for every generated and vendored file are in
[`provenance.json`](./provenance.json).

## Layout

Two Trunchbull Repositories, `parsebench-pdf` and `parsebench-image`. Each
package directory below is the root of its own Repository.

```text
parsebench/                  shared tooling and documentation (this repo only)
├── grader/                  canonical grader context (Dockerfile, server, upstream code)
│   └── rules/               dataset: generated, never committed (protected)
├── parsebench-pdf/          Repository: attaches the original document
│   ├── benchmark.config.ts
│   ├── evals/parse-with-layout.ts
│   ├── transformers/index.ts
│   ├── data/documents.jsonl
│   ├── trunchbull.data.json dataset manifest (path, sha256, size of every data file)
│   ├── documents/           dataset: generated, never committed (protected)
│   ├── grader/              byte-identical copy of ../grader
│   └── README.md, NOTICE, LICENSE.upstream, .trunchbullignore
├── parsebench-image/        Repository: attaches 150 DPI PNG renders
│   └── …                    same shape as parsebench-pdf
├── tools/                   prepare.sh / prepare.py, sync-grader.sh, write_provenance.py
└── parity/                  grader-vs-upstream score and latency checks, reports
```

**Dataset files never live in Git.** The source documents, their PNG renders
and the upstream rule files are dataset content. In this public repository
they are gitignored and regenerated by `tools/prepare.sh` from the pinned
Hugging Face revision, with every file hash-verified. In a Trunchbull
Repository they are protected objects. Each package's `.trunchbullignore`
covers `documents/` and `grader/rules/`. Git holds only the small pointer
(`oid sha256:…`, `size …`), and the bytes live in R2. What Git holds per
Repository is then just code, manifests, the vendored upstream source and
pointers, about 6 MB. That is far below Cloudflare Artifacts' 1 GB Repository
and 64 MiB push limits, whatever the dataset size. The licence decides only
whether a Repository may be publicly mirrored (it may not; see
[Licensing](#licensing)), not where the bytes are stored.

Each Repository carries its own copy of the grader: grader contexts and
attachments must live inside their package. `tools/sync-grader.sh` writes the
copies and `--check` verifies them. The copies are byte-identical, pointers
included, which gives both Repositories the same grader context digest: one
image build and one grader deployment.

## Cases

Upstream's loader (`parse_bench/test_cases/loader.py`) makes one test case
per (category, document). Text documents are scored twice, by the Content
Faithfulness rules and by the Semantic Formatting rules, so they appear as two
cases. That is 2,553 cases in total:

| Group             | Upstream dimension   | Headline metric (upstream default) | Cases |
| ----------------- | -------------------- | ---------------------------------- | ----: |
| `table`           | Tables               | `grits_trm_composite`              |   503 |
| `chart`           | Charts               | `rule_pass_rate`                   |   568 |
| `text-content`    | Content Faithfulness | `content_faithfulness`             |   506 |
| `text-formatting` | Semantic Formatting  | `semantic_formatting`              |   476 |
| `layout`          | Visual Grounding     | `layout_element_rule_pass_rate`    |   500 |

The transformer is deterministic and reads only `data/documents.jsonl`. Each
case's `data` is just `{ document, kind }`: the upstream document path and
the case kind. The rules never leave the grader context, and the model can
never read the grader image.

Package case counts after the platform's attachment limits are applied are in
`provenance.json` (`packages.*.cases`) and summarised under
[Known differences](#known-differences-from-upstream).

## Grader

`grader/` builds a Python 3.12 image (base images pinned by digest). It
installs the vendored, unmodified upstream source from its own `uv.lock`
(core dependencies plus the `anthropic` extra). It serves the Trunchbull grader
protocol on port 8080 (`GET /health`, `POST /evaluate`). For each request the
grader:

1. Checks that the trial's attachment hashes are the pinned document, which
   also tells it which package the trial came from.
2. Rebuilds the raw output upstream's `AnthropicProvider` records for that
   page from the model's text. It uses `parse_layout_blocks` and the page
   geometry upstream records (PDF points for the PDF package, pixel size for
   the PNG package), then calls the provider's own `normalize()`.
3. Runs upstream's `EvaluationRunner.run_evaluation` with the `parse-bench run`
   defaults on a one-case copy of the dataset.
4. Returns the group's headline metric, unrounded, as the score. It applies
   upstream's aggregation rules: a genuine failure scores 0; a result upstream
   would leave out of its average still scores 0, with
   `details.aggregation` set to `skipped` or `metric_absent`.

The rules for all 2,553 cases are baked into the image at build time
(`build_index.py`). The build also checks every per-case shard against
upstream's full-dataset loader. The running grader makes no network calls,
and the parity check runs it with networking disabled.

## Preparing the documents

```sh
benchmarks/parsebench/tools/prepare.sh [cache-dir]
benchmarks/parsebench/tools/sync-grader.sh
python3 -I benchmarks/parsebench/tools/write_data_manifests.py
```

`write_data_manifests.py` writes each package's committed
`trunchbull.data.json`. It lists every dataset file (documents, renders and
rules) with its sha256 and size. Trunchbull's official-Repository tooling
(`pnpm benchmarks:repository:prepare` / `…:migrate`) verifies the regenerated
files against it, commits protected-object pointers in their place, and
uploads the bytes to R2 before it pushes.

`prepare.sh` runs `tools/prepare.py` in a digest-pinned `linux/amd64` Python
image with hash-locked PyMuPDF 1.28.2 and Pillow 11.1.0 (the versions in
upstream's `uv.lock`). It:

- downloads every document and rule file at the pinned dataset revision;
- writes the rule files, gzip-compressed, to `grader/rules/`;
- verifies each one against the Hugging Face tree metadata (LFS sha256, or
  the Git blob sha1 for small files);
- renders each page to PNG at 150 DPI with the long edge capped at 2,000 px;
- writes both packages' `data/documents.jsonl` and `grader/documents.json`,
  which records each source sha256 next to its PNG sha256s and page geometry.

Re-running it reproduces the same bytes. `provenance.json` records the
hashes of the generated manifests.

## Parity

```sh
benchmarks/parsebench/parity/run.sh [cache-dir] [per-category]
```

The script builds the grader image and runs `parity/parity.py` inside it with
`--network none`. Reference outputs are built from the ground truth in four
styles: faithful, degraded, plain markdown, and empty. Each output is scored
two ways:

- **Upstream path.** Upstream's real `AnthropicProvider.run_inference` is
  driven by a stub client that returns the reference text. It reads the real
  PDF or PNG. The results are scored with upstream's normal multi-case
  evaluation.
- **Grader path.** The same output goes through the grader's
  `POST /evaluate`.

Scores must match exactly, case by case. The last report is
[`parity/report.json`](./parity/report.json). It covers 8 documents per
category × 4 output styles × 2 packages, which is 320 grader requests. The
grader matched upstream exactly on every request: 288 scored, 76 of them
fractional, and 32 that upstream drops from its average. Each category's
run-level mean also equalled upstream's `avg_<metric>`. A sample can include
the same document in more than one category, so the reference run uses one
inference output directory per category. Upstream shares a single `text/`
result between `text_content` and `text_formatting`.

The same check on a `linux/amd64` build, the architecture Cloudflare runs, is
in [`parity/report-amd64.json`](./parity/report-amd64.json). It covers 3
documents per category, 120 requests, with 0 mismatches. Its scores are
bit-identical to the arm64 run for every shared case.

`parity/latency.sh` times the heaviest cases at the declared instance size
(1 vCPU, 6 GiB); results are in
[`parity/latency.json`](./parity/latency.json). Most cases take well under a
second and large tables up to about 7 s. The one Content Faithfulness page
with 3,302 rules (`text_ocr__paper8col.pdf`, median 244) took about 50 s,
close to the platform's 60 s grader request timeout.

## Licensing

- **Code**: upstream ParseBench is Apache-2.0 (`LICENSE.upstream`, `NOTICE`).
  This port's own files are offered under the same license.
- **Dataset**: the Hugging Face card declares Apache-2.0. It also says the
  documents are "sourced from public online channels". The pages come from
  third-party publishers: UN and OECD publications, company annual reports,
  SERFF insurance filings, and government reports. No per-document license is
  recorded. Apache-2.0 from the dataset authors cannot grant rights in
  documents they do not own, so redistribution of the PDFs and their renders
  is **not established**.
- **Consequence**: neither Repository may be publicly mirrored. Storage does
  not depend on the licence: documents, renders and rules are dataset files,
  so they are always protected objects (see [Layout](#layout)) and never
  appear in this or any Git history.

## Known differences from upstream

- **One request per document.** Upstream sends each page of a multi-page
  document in its own request; Trunchbull sends the whole document once. The
  grader records the single response as page 0, which affects only the
  multi-page documents listed in `provenance.json`.
- **Output cap.** Trunchbull caps output at 16,384 tokens; upstream's Anthropic
  pipelines allow 32,768.
- **Attachment limits.** Documents over Trunchbull's 10 MB-per-attachment
  limit are left out of the PDF package (listed in `provenance.json`), so its
  case count is below 2,553.
- **Image encoding.** The PNG package sends lossless PNG renders; upstream's
  Anthropic image mode re-encodes pages as JPEG.
- **Excluded results.** Run-level means include the zeros described in
  [Grader](#grader) step 4, so they can differ slightly from upstream's
  averages, which drop those cases.

## Before the first build

Platform gaps found while porting. None are worked around here:

- `task/parsebench-foundations` must be merged and the tool deployer
  redeployed.
- Binary protected objects fail the build:
  `loadProtectedRepositoryFiles` (`apps/api/src/lib/repository-protected-object.ts`)
  decodes them as strict UTF-8. It also loads every protected object into
  Worker memory at once, and these Repositories hold about 430 MB and 820 MB.
  Attachments and grader contexts should resolve pointers straight from R2.
- Nothing yet runs `tools/prepare.sh` and uploads its output as protected
  objects when official Repositories are prepared or migrated.
- The CLI protected-file limit (10 MB) matches the attachment limit, so the 8
  oversized PDFs cannot be stored or attached.
- The grader request timeout is fixed at 60 s; the heaviest case takes about
  50 s on 1 vCPU (see [Parity](#parity)).
